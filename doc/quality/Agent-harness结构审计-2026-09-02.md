# Agent harness 结构审计（2026-09-02）

## 结论

`test-results/2ffb3694c37/1.json` 的失败由 harness 提前终止。该运行只用了 3/12 个模型轮次、0/32 次工具调用、约 16k/120k 输入 token 和 4.4k/24k 输出 token。用户选择的 `deep` 预算仍有大量余量。

本轮直接触发点是录入 Agent 的两次计划修正上限。深层原因有四项：

1. 首轮要求模型一次声明完整 typed plan，并禁止调用工具。
2. 给模型的人物索引按 2,000 字符截断，只包含前 15 个人物；索引没有完整性与游标声明。
3. 同一提示又声明圈层批改前必须调用 `get_collections`，与首轮禁用工具冲突。
4. 圈层没有进入录入任务账本的一等 domain，只能暂借 `person.changes.circle`，再由界面提交阶段转换成集合成员关系。

模型第一次把许薇的 ID 配给周明远，第二次为不可见人物编造 ID。编译器正确拒绝了错误引用，但修正轮没有获得新的档案内容或新的工具权限，第三次仍在相同信息条件下重写同一份大计划，最终失败。

## 本次数据的两个独立问题

### 第二次操作的契约失败

第二次操作要求为全库人物整理圈层。日志显示：

- 第 1 轮：`person-18` 将周明远绑定到许薇的稳定 ID。
- 第 2 轮：周明远、李刚、陈敏改用三个不存在的占位 UUID。
- 第 3 轮：继续返回相同占位 UUID，运行被两次修正上限终止。

因此，“任务计划不符合执行契约”并不代表第一次录入时写坏了稳定 ID。第二次运行拿不到完整 ID 集合，却必须提交完整 ID 计划。

### 第一次录入的语义错误

第一次录入已成功创建稳定记录，但关系语义仍有一处错误：材料中的“周明远（我舅舅的老同学）”被保存为“我 → 周明远：舅舅的老同学”。合理的原子事实应是“舅舅 ↔ 周明远：老同学”。

这属于指代和所有格解析错误。它没有造成第二次运行的 ID 契约失败，却会影响后续引荐路径和圈层判断。结构化输出合法不等于语义正确。

## 四层预算

| 层级 | 当前机制 | 用户可调 | 典型影响 |
| --- | --- | --- | --- |
| 整次运行预算 | quick / standard / deep 的轮次、工具数、累计输入输出 token、总耗时 | 是 | 真正耗尽时停止 Agent |
| 单轮传输包络 | prompt 最多约 31.8k 字符；历史最多 8 轮、单轮 6k、合计 24k | 否 | deep 仍看不到被裁掉的内容 |
| 披露与记忆预算 | 录入索引每类 2k；通用 Agent 首屏 12 人；工具结果通常投影到 3.8k；工作记忆 12 条/14k | 否 | 大库中产生首屏偏差、重复检索和 ID 不可达 |
| 协议状态预算 | 录入最多两次修正；部分 Agent 每轮一个工具；推荐固定三跳、三个候选 | 否 | 经常早于 token 预算终止，错误信息却容易归因于预算 |

高级设置适合管理第一层。后三层涉及协议正确性和上下文工程，应由 harness 自动处理，并在运行轨迹中披露省略情况。

## 各入口的当前机制与失效条件

### 录入 Agent

当前链路：材料与上一版草稿 → 压缩档案索引 → 模型一次性声明 typed plan → 本地编译稳定 ID → 生成待确认草稿 → 用户批准 → 本地事务写入。

主要失效条件：

- 请求涉及截断索引之外的人物、关系或事件。
- 请求要求全库批处理，完整计划超过模型单轮可可靠维护的规模。
- 请求涉及圈层，工具注册要求先读集合，状态机却禁止工具。
- 修正错误只告诉模型“哪个 ID 错了”，没有返回正确候选、游标或可执行的检索动作。
- 复杂所有格、转述和多层指代通过 schema 校验后仍可能写成错误语义。

模型灵活性受限点：模型必须同时做语义理解、稳定 ID 抄写和全批次编排；任何一项失败都会拒绝整批。稳定 ID 抄写本应由本地解析器承担。

### 通用“问一问” Agent

当前链路：最近对话 → 首屏档案摘要或 12 人索引 → 模型每轮选择一个工具、提案或最终回答 → 工具结果投影进历史 → 本地引用核验或事务编译。

主要失效条件：

- 大库检索需要多页时，每页占一个模型轮次。
- 工具结果超过投影预算，后续轮次只看到部分字段或部分行。
- 中间对话超过 8 轮时，较早内容只剩最多 520 字的首尾摘录，承诺、排除条件和中间纠正会消失。
- 工具记忆只保留 12 条且按整库版本失效；任何无关档案变化都会清空全部复用结果。
- 暂停检查点、聊天和工具记忆保存在 React 内存；当前页面内切换已通过保留挂载维持，刷新、关闭标签或重新打开仍会丢失。
- 非变更回答连续两次结构无效会整轮失败；可以降级显示的自然语言也被丢弃。

预算提高能增加分页和修正机会，无法恢复已经压缩掉的对话语义，也无法跨刷新恢复内存状态。

### “这事该拜托谁”推荐 Agent

当前链路：模型先判断开放任务或目标人物 → 本地算法计算路径或能力槽候选 → 候选、顺序和可达状态锁定 → 模型读取证据并润色话术 → 最终对象必须逐字复述本地锁定结果。

主要失效条件：

- 能力匹配依赖档案字符串包含模型给出的搜索词或二元片段；语义相近且措辞不同的人会在模型复核前被排除。
- 目标路径固定最多三跳；第四、第五跳即使存在也不会进入当前推荐调用。
- 默认不使用推导关系；缺少联系方式、亲密度和互动记录时，显式关系仍可能因接入边约束而无法形成引荐路径。
- 本地候选为空后，模型只能解释空结果，不能通过阅读更多档案提出可核验的新候选。
- 模型未逐字复述锁定 decision 会进入格式修正，即使本地已经拥有可展示的正确候选。

这里的确定性算法适合验证证据、计算路径和稳定排序。语义召回也由确定性词面匹配封闭后，模型的理解能力无法参与候选发现。

### 行动规划 Agent

当前链路：只给模型档案数量 → 模型逐轮检索人物/关系/事件 → 最后一轮保留给任务草案 → 本地移除未披露或无效 ID → 用户批准任务。

主要失效条件：

- 具体目标涉及多人和多类资料时，每轮一个工具会快速消耗 standard 的 7 轮。
- 运输重试耗尽后没有与通用 Agent 等价的持久检查点，已有检索结果会随运行失败丢失。
- 最终轮到来前没有取得人物 ID 时，计划只能退化为不绑定人物的通用任务。

它对无效人物引用采用移除并提醒，降级方式优于整批失败；恢复与记忆仍未统一。

### 单次 AI 旁路

人物卡“AI 自动整理”、卷宗材料抽取、图片 OCR、模糊日期、祝福语、部分调查与识别摘要直接调用 `askModel` / `askText`。这些路径不使用 AgentRuntime，因此：

- 高级预算不会影响它们；
- 没有统一轮次、工具、检查点和 Agent 日志；
- 失败恢复策略各自实现；
- 卷宗抽取当前会直接写人物与待确认关系，绕过统一提案收据，和“三方边界”不一致。

单次推理可以保留轻量实现，但凡会修改档案，都应进入统一提案与事务协调器。

## 横向结构性矛盾

### 1. 计划先于发现

录入 Agent 在完整发现目标之前要求完整计划。缺少 ID 时，模型只有复用错误 ID、编造 ID 或漏掉人物三种结果。可靠顺序应为：理解意图 → 发现并解析引用 → 声明语义变更 → 本地编译事务。

### 2. 模型承担数据库引用完整性

模型适合输出“把周明远放进同事圈”这类语义引用。本地应将姓名、别名、当前选中对象和 recordRef 解析为稳定 ID；存在歧义时只把歧义项交给用户。当前要求模型复制 UUID，浪费上下文并扩大失败面。

### 3. 部分披露缺少可操作的完整性语义

推荐和问答的首屏索引带有 `profileIndexComplete` 与 `nextProfileCursor`，录入索引没有。日志又把长字符串统一截到 8k，审计时看不到真实请求尾部。运行轨迹需要同时记录：总记录数、已披露数、游标、被省略字段和本轮实际发送字符数。

### 4. 修正循环没有增加信息

有效修正必须改变条件，例如返回正确候选、开放一次检索、缩小到失败子集或把歧义交给用户。当前录入的三轮收到同一截断索引；推荐的 decision 修正也只要求重新抄一遍本地已有结果。重复采样不能解决信息缺失。

### 5. 本地算法提前封闭语义空间

推荐候选由词面匹配先过滤，模型只能在封闭集合内写解释。合理边界是模型负责语义召回和任务理解，本地账本验证每条证据、路径、权限与排序因子。零词面命中可以降低置信度，不能直接等价为零候选。

### 6. 恢复、记忆与日志仍非统一能力

通用 Agent 有传输重试和内存检查点；规划与录入没有同等恢复；单次旁路没有 Agent 日志。当前“统一 Runtime”覆盖了预算和工具注册的一部分，尚未覆盖会话、检查点、上下文账本和所有写入路径。

## 重构优先级

### P0：让录入批处理可完成

1. 将录入状态机拆为 `UNDERSTAND → DISCOVER → RESOLVE → PROPOSE`。
2. typed plan 输出语义引用；稳定 ID 由本地解析。模型只有在本地返回多个候选时参与消歧。
3. 把 collection 与 membership 纳入一等变更 domain，直接复用 `propose_archive_mutations` 的集合事务。
4. 全库命令由本地枚举目标集合；模型输出分类规则或逐人语义标签，本地按 ID 批量编译。
5. 单项无法解析时保留其余可执行项，输出“已完成 / 待消歧 / 被拒绝”收据，不再让一个坏 ID 吞掉整批。

### P0：统一持久恢复

将聊天、工具记忆、暂停检查点和未批准提案保存到浏览器本地会话记录。刷新后恢复同一 run；档案发生相关变更时只失效依赖该记录的缓存，不清空全部记忆。

### P1：开放推荐的语义召回

1. 模型可提出候选人物 ID 或检索查询，本地逐条验证档案证据。
2. 词面匹配保留为高精度证据命中与排序特征，取消其候选准入权。
3. 路径深度根据图规模和任务自动扩展到安全上限；界面可提供用户策略，但默认自动。
4. 本地已有候选时直接渲染；模型 decision 格式错误只影响话术，不重新计算或吞掉候选。

### P1：建立上下文账本

用结构化上下文账本记录已经披露的记录 ID、字段、来源版本、遗漏原因和游标。对话压缩保留用户约束、已确认结论、待办和引用，替代首尾 80 字摘录。

### P2：收口单次旁路

只读的 OCR、日期解析和文案生成可保留单次推理；所有档案写入统一生成待批准提案。单次推理接入统一传输重试、日志元数据和错误分类。

## 高级设置边界

适合用户调整：

- quick / standard / deep 与自定义累计轮次、工具数、token 和总耗时；
- 档案写入授权方式；
- 是否允许已确认推导关系参与推荐；
- 本地会话与检查点保留期限、日志保存级别和存储上限；
- 推荐偏好中的最大引荐距离，可提供“自动 / 2–5 跳”。

必须由系统保证：

- 稳定 ID 可达性和分页完整性；
- 集合与成员关系的权威写入路径；
- 引用完整性、事务原子性、删除级联和撤销；
- 提示词、schema、解析器与工具注册一致；
- 修正轮获得新增信息；
- 语义召回不会被首屏顺序或词面门槛截断。

这些正确性条件不应成为高级开关，否则用户会被迫替 harness 调参。

## 验收标准

- 50、500 人档案中执行“为所有人物整理圈层”，无须模型复制全库 UUID，单个歧义不阻塞其余变更。
- 任意人物位于分页尾部时，录入、问答、推荐和规划都能定位到同一稳定 ID。
- 修正轮的输入必须比失败轮多出候选、工具结果或缩小后的错误子集。
- 4–5 跳关系存在时，自动路径策略能够发现并标明距离与证据。
- 同义能力案例可进入候选核验，最终证据仍必须来自本地档案。
- 刷新页面后可恢复聊天、工具结果、暂停轮次和未批准提案。
- 日志能区分“运行预算耗尽”“单轮上下文省略”“协议拒绝”“传输失败”，并记录实际披露计数。
