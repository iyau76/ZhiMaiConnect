> 工作分支：`refactor/staged-upgrade-20260904`

## 三套合成归档

生成器位于 `tests/fixtures/archive-fixtures.ts`，固定导出时间、稳定 ID 和合成联系方式；测试不会读取真实浏览器档案。

| 夹具 | 人物 | 事实关系 | 派生投影 | 圈层 | 成员关系 | 事件 | 提醒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `empty` | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| `demo-50` | 50 | 80 | 7 | 6 | 50 | 25 | 3 |
| `stress-500` | 500 | 809 | 70 | 6 | 500 | 250 | 30 |

`tests/archive-fixtures.test.ts` 对三套归档逐一执行：

```text
生成 archive@2
→ 生产导入函数写入 IndexedDB
→ 生产导出函数再次导出
→ 清空全部权威记录
→ 导入刚导出的 archive@2
→ 丢弃旧投影并由当前 projector 重建
→ 比较全部权威记录与投影不变量
```

固定不变量：

- 每类一等记录 ID 唯一；人物、圈层、事件、提醒和支持事实引用完整；
- 事实关系与派生关系分开，导入时不把归档中的派生快照当权威真相；
- 圈层成员以 `collectionMemberships` 为唯一来源；
- 导出、清库、导入和投影重建后，权威记录逐 ID 相同；
- 联系方式只使用 `example.invalid`，夹具和日志不含 API Key、Cookie 或真实联系人。

单独验证：

```bash
npx vitest run tests/archive-fixtures.test.ts
```

## 故障分类

运行日志只使用以下五个执行分类；产品缺陷再映射到相应所有者：

| 日志分类 | 含义 | 产品层 |
| --- | --- | --- |
| `transport` | 5xx、超时、连接中断 | 外部传输 |
| `budget` | 整次运行预算耗尽 | 执行 |
| `context_omission` | 字段、记录、历史或游标被省略 | 数据 / 执行 |
| `contract` | 模型输出或工具输入不符合协议 | 执行 |
| `transaction` | 提案、批准、提交或撤销失败 | 数据 |

交互层问题单独记录，例如状态不可见、按钮语义不清、恢复入口缺失。一个错误只能有一个主分类，可附带上游原因，避免把 503、预算和协议拒绝都显示成“模型失败”。

## 测试产物约定

新增人工或真实 API 结果使用：

```text
test-results/<YYYY-MM-DD>/<flow>/<run-id>/
```

每个 run 最多包含一份脱敏输入摘要、一份结构化运行日志和必要截图。真实 API 日志保留 provider、模型、预算、步骤、耗时、token 与错误分类；默认不保存完整提示词、档案正文、密钥和联系方式。历史目录不为统一命名而批量改名。

## 低优先模块维护策略

人脸、声纹、调查、企业项目和平台连接器在阶段 0/1 只修阻断主流程、数据损坏或隐私边界的错误。新增入口、模型能力或展示效果推迟到主流程恢复、稳定引用和事务账本验收之后。
