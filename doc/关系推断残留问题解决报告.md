# 关系推断残留问题解决报告

> 完成日期：2026-08-28
>
> 问题基线：`doc/关系推断残留问题清单.md`
>
> 原则：基线文档保留原样；其建议不是实现指令，下面记录经过复核后的最终方案。

## 1. 结论

本轮没有停在“多写几条提示词”。关系已进入录入智能体的检索、读取、暂存、校验、确认和提交闭环；常见亲属闭包由本地规则引擎计算，模型主要负责识别材料中明确出现的人物和基础关系。

由此解决了三类根因：

1. 关系不再是智能体循环之外的附属 JSON 数组；
2. 推导边有规范语义、基础边依赖、去重键和失效机制；
3. 兄弟姐妹、祖孙、曾祖、叔姑舅姨、姻亲、继亲和表堂关系不再只依赖模型“心算”。

## 2. 结构性问题处理

| 基线编号 | 状态 | 最终处理 |
| --- | --- | --- |
| S1.1 工具不对称 | 已解决 | 录入智能体增加关系检索、读取和暂存更新；人物详情返回去敏关系摘要。“问一问”增加关系修改提案。 |
| S1.2 两套暂存状态 | 已解决 | 人物、事件和关系统一写入一个暂存 `IngestCandidate`，按稳定键 upsert；终稿与暂存按键合并，不再盲目拼接数组。 |
| S1.3 校验在循环外 | 已解决 | JSON 语法错误、Zod 契约错误、AI 关系无依据、依据前缀错误均写回工具历史，最多自动修复两轮。提交时保留第二道门禁。 |
| S1.4 历史截成坏 JSON | 已解决 | 人物录入与通用问答共用按完整条目裁剪的历史序列化器，不再对整段 JSON 做字符串尾切。 |
| S1.5 单工具/固定八轮 | 已解决 | 循环扩为 12 轮，明确 PLAN、SEARCH/STAGE、VERIFY、FINAL 阶段；一轮可批量执行最多四个独立读取工具。 |
| S2 重复边与陈旧推断 | 已解决 | 提交按端点、方向和 `semanticKind` 去重；推导边写 `derivedFromRelationIds`；基础边改删后依赖边退回待确认并避免用于推荐。 |
| S3 明说关系无依据 | 已解决 | AI 路径要求每条关系的 `basis` 以“原文：”或“推断依据：”开头；人工手建关系仍可不填，避免把模型约束错误施加给用户。 |
| S4 新材料被长前缀挤掉 | 已解决 | 11,800 字符预算中为本轮材料保留至少 3,000 字符，优先裁剪过长前缀/旧草稿。 |

### 架构取舍

基线建议把 `basis` 直接改成 Zod 必填。最终没有照搬：同一个 `IngestRelation` 也承载用户在草稿页手动新增的关系，强制必填会损害手动录入。现在采用“公共数据结构可选、AI 解析边界必填、提交边界按来源复核”的分层约束，既保证 AI 可审计，也不阻断人工记录。

人物与关系修改不再各自在界面写一套批准逻辑。`archive-update-tool` 以判别联合统一创建提案、生成差异和批准执行；所有 AI 写操作都只生成提案，批准前 IndexedDB 不变，数据已变化时旧提案自动失效。

## 3. 本地亲属闭包

`kinship-engine` 只使用带“原文/Original”依据的基础边，以及本轮由这些基础边确定性产生的短闭包。生成边统一带：

- `note: 本地亲属规则推导，需核验`；
- `basis: 推断依据：…`；
- `confidence: 0.7`；
- 入库后的 `evidenceMode: inferred` 和基础关系 ID。

当前覆盖：

- 共同父母 → 兄弟姐妹；有两侧另一位父母证据时区分同父异母、同母异父；
- 两代父母链 → 祖孙/外祖孙；三代父母链 → 曾祖孙；
- 父母的兄弟姐妹/兄弟姐妹的子女 → 叔伯侄、姑侄、舅甥、姨甥；
- 配偶 + 配偶父母/兄弟姐妹 → 翁媳、婆媳、岳婿或中性姻亲；
- 继父母 + 其亲生子女 → 继兄弟姐妹（无血缘）；
- 兄弟姐妹各自子女 → 堂亲、姨表亲或中性的姑舅表亲；
- 同宗/族亲、爷爷/祖父、姥姥/外婆等称谓进入统一 `semanticKind`。

未写长幼时只生成“兄弟姐妹”“叔伯侄”等中性标签，不猜哥哥/弟弟、姐姐/妹妹。姑表与舅表对双方称谓本来可能不对称，单条双向边无法同时表达两种视角时使用“姑舅表亲”，避免为了命中测试而造出错误方向。

普通同事、同学和合作关系不进入亲属闭包；只能按材料明说输出。

## 4. 文档矛盾修订

- 样例 1.1 改为“爸爸 → 我、爷爷 → 爸爸、爷爷 → 我”，统一长辈在 `from`；
- 样例 3.4 将“薛蟠是薛姨妈的哥哥”改为“薛蟠是薛姨妈的儿子”；
- 明确推导关系在草稿阶段待确认，用户逐条接受后入库为 `confirmed`，但永久保留 `evidenceMode: inferred`、低置信度、依据和依赖链。

## 5. 验证结果

- 静态检查：TypeScript、ESLint、Prettier 全通过；
- 单元/组件测试：覆盖智能体修复回合、批量工具、关系暂存合并、亲属闭包、语义归一、依赖解析、关系修改批准和 200 人性能守卫；
- 浏览器回归：覆盖人物与关系写入批准、录入更新、撤销、关系图四视图、目标引荐、50 人 80 边压力场景和三档响应式尺寸；
- 生产构建：Cloudflare module preset 构建成功。

模型仍负责把自由文本标注为明确人物和基础边，因此无法把“所有自然语言理解错误”数学上归零；但关系推导、审计、去重和失效已经从提示词概率行为下沉为可测试的本地机制。
