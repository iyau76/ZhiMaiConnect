# 关系网与推荐升级实施报告

> 实施日期：2026-08-28
>
> 范围：关系数据 V9、关系图分层、目标人物引荐、推荐智能体路径工具与自动化测试

## 1. 数据契约

`RelationRecord` 新增以下可选字段，并保持旧数据兼容：

- `evidenceMode`：材料明确、推导或旧数据未知；
- `confidence`：关系事实置信度，缺失时保持未知；
- `visibility`：`always / auto / hidden`，只控制关系图；
- `recommendationPolicy`：`allow / avoid / block`，独立控制引荐资格；
- `semanticKind`：规范语义类型，保留原始 `label`；
- `derivedFromRelationIds`：推导关系依赖的基础关系。

IndexedDB 由 V8 升至 V9。迁移只从明确的 `原文：` / `推断依据：` 前缀识别证据模式，其余旧关系标为 `unknown`，不猜测置信度。基础关系被修改或删除时，带依赖 ID 的推导关系自动退回待确认，并改为“尽量避免用于推荐”。

## 2. 关系图

关系图提供四种视图：

1. **概览**：显示用户常显边、结构桥、显著关系，折叠结构冗余的推导边和平行低优先关系；
2. **聚焦一跳**：显示选中人物的一跳上下文，其他人物保留但淡化；
3. **聚焦两跳**：按需扩展到两跳；
4. **全部**：包含常隐关系，用于完整核查。

显著性计算使用确认状态、证据模式、可选置信度、更新时间、共同事件和来源。缺失置信度采用中性值，不按零分处理。所有权重集中在纯函数中，属于可测试、可替换的产品参数。

支持按原始标签、规范类别、证据模式和确认状态筛选。每条关系可独立设置展示策略和推荐策略；“常隐”不会删除关系，也不会自动禁止推荐。

## 3. 推荐双模式

### 3.1 开放式求助

“谁懂合同”“谁适合拍照”等没有指定目标人物的问题，继续使用任务事实、用户亲密度、联系方式和近期互动进行本地候选排序。

### 3.2 目标人物引荐

问题中命中档案姓名且含“找、联系、引荐、办事”等意图时，进入目标模式：

1. 建立不入库的虚拟“我”节点；
2. 只连接到确有联系方式、亲密度或个人互动证据的人；
3. 将关系箭头视为语义方向，引荐遍历默认双向；
4. 排除拒绝、待确认、禁止推荐的关系；默认排除推导关系；
5. 枚举最多三跳的简单路径，按非负累加成本稳定排序；
6. 每个首位联系人只保留成本最低的路径。

多人姓名同时命中时不猜目标，要求用户选择。找不到合格路径时直接提示补充关系或确认推导关系，不退化为无关人物的关键词评分。

## 4. 智能体边界

推荐智能体新增本地只读工具 `find_connection_paths`。工具返回 `rankingLocked: true`，目标模式下的候选、分数、顺序、人物 ID、关系 ID和路径均由本地确定性算法生成。AI 只生成比较说明、逐跳沟通建议和可编辑话术。

人物联系方式原文仍不进入工具返回；联网天气与搜索工具也不携带人物档案。

## 5. 验证覆盖

- V8→V9 迁移与保守字段回填；
- 基础关系变更后的推导依赖失效；
- 常显、常隐、全部视图与结构桥保留；
- 显式两跳已存在时折叠冗余推导边；
- 一跳/两跳焦点范围；
- 目标识别、多人目标消歧；
- 红楼梦式“我→贾琏→贾母”路径；
- 与目标断开的高亲密度人物不得入选；
- 语义单向边仍可用于双向引荐遍历；
- 待确认、推导和禁止推荐边的默认排除；
- 展示常隐与推荐禁用相互独立；
- 200 人合成图的有界性能回归；
- Playwright 覆盖视图切换、单边策略持久化、目标路径和 50 人 80 关系图。

## 6. 本轮明确延后

- 家庭成员组、fan、connector、clique 的图形化折叠字形；
- Personalized PageRank；
- 边捆绑与社区发现；
- 从用户选择记录学习路径权重；
- 超过 200 人的虚拟化和 500/1,000/5,000 人性能基准。

这些项目需要真实使用反馈或更大规模测试，不在没有证据时提前增加复杂度。
