# DeepSeek 真实 API 验收记录（2026-08-28）

本记录使用浏览器真实操作本地开发版，并调用官方 DeepSeek OpenAI 兼容接口。密钥只注入测试进程，没有写入仓库、测试报告或浏览器持久档案。

## 已通过的主线

- DeepSeek 连接：`deepseek-chat` 请求成功。
- 复杂亲属录入：同一段红楼梦关系材料连续运行两次，均成功形成并提交 26 个人物、24 条以上原文事实关系；人物身份稳定，事实去重、派生关系可追溯和投影数量上界均成立。两次模型会使用“父亲/儿子”“妻子/嫁给了”等不同表述，因此不再把“逐边字符串完全相同”当作正确性条件。
- 已有关系修改：模型读取稳定关系 ID，生成“同事→前同事”待批准计划；批准前不写库，批准后生效，再次询问能够从新事实关系读取“前同事”。
- 圈层批量整理：能够先读取圈层与成员，生成一个批量提案；批准后把红楼梦人物移入“虚构”圈层，同时保留真实亲属不变。
- 人物删除级联：模型调用专用原子删除工具并等待批准；批准后删除人物与独占关系、事件、提醒、待办和项目，共享记录只解除人物引用，圈层成员同步清除，证据正文保留但不再绑定已删除 personId。
- “找贾母办事”：没有本人可达路径时，Agent 仍在第一次模型调用前真实执行路径和目标侧入口工具；AI 能看到目标侧档案，同时不会伪造“本人已可联系”的路径。
- Agent 预算与日志：自定义轮次、工具次数、输入/输出 token 和总时限能够持久化；工具上限为 0 时在执行前终止并留下可审计原因；日志可以清除。

## 真实测试发现、尚未完成的事项

1. 连续补录已经复用已有人物并正确推导兄弟姐妹、祖孙和表亲，但“贾政—林黛玉”目前显示通用“叔伯侄”，没有按母系分支精确成“舅甥”。这是亲属分支语义缺口，不应通过改测试掩盖。
2. 同一轮同时修改人物职位、事实关系和事件日期时，DeepSeek 能依次检索并暂存人物与事件更新，但默认八轮内没有完成关系更新，最终没有形成可确认草稿。需要把多域编辑改成显式任务状态机，而不是继续增加提示词或盲目加轮次。
3. “50 人户外活动，需要场地、急救和视觉物料”仍被单一总分排序吞掉多个能力域，只返回视觉候选。多人协同任务应先拆成能力槽位，再对每个槽位独立召回和组合，不应只调权重。

## 本轮据此完成的结构修正

- 档案事实引用以稳定 `sourceRef` 为选择器；模型的 quote 只作定位提示，最终事实字段由本地记录选取和渲染，避免模型已选对记录却因措辞不同而整轮失败。
- 关系兼容边界统一识别“父亲、母亲、儿子、女儿、孩子、哥哥、妹妹、嫁给了”等常见标签，使新写入能进入稳定谓词和本地投影；长期方案仍是让模型直接输出谓词与限定符。
- 新增 `propose_person_deletion` 专用工具；`delete_person` 是一个完整原子级联操作，不再要求模型逐项拼接依赖清理。
- 写操作门禁覆盖句首“删除/移除”，不允许模型用文字声称“计划已生成”而绕过提案事务。

这些结论以 `doc/中期反思.md` 的产品边界为准：模型负责理解，本地账本负责可证明的执行，人以可撤销收据批准写入。
