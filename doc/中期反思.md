# 中期反思：确定性、智能与人的边界（v3）

> 记录日期：2026-08-29 ｜ 定位：产品哲学与架构判据，随实践持续修订
> v3 变更：① 新增 P8「结构优先于补丁」与 P9「用户优先于非底线核验」；② 第 5 节从"问题流水账"改为"已解决 + 未解决"两张表，删除已解决问题的过程细节；③ 新增 F 裁决：输出契约类型化。
> 本次修订的直接诱因：「当前人物档案还缺哪些信息」的答案只有抽象的 ①–⑤，具体到人的内容被模型放进 archiveClaims 后因渲染层不认"缺失声明"而 citationCount=0 静默丢弃（证据：`test-results/c018e72e94测试/新的一轮结果.json`）。

---

## 1. 问题的重新表述

用户输入无法预定义，这是事实。LLM 把"理解自由文本"的成本降到了可商用水平，但一个关系记忆产品的承诺不是"理解"，是**可信**。

于是两股力量相遇：智能是概率性的，适合理解；可信是确定性的，需要账本。过去的错误不是"确定性用多了"，而是把两者放在同一对象上竞争——正则假装理解语义，模型假装记账。解法是拆维度：**理解归模型，事实归账本，批准归人。** 批准可以是一键收据，不必是收费站。

---

## 2. 历史复盘（压缩版）

1. **阶段一（6fd7028）**：薄数据契约 + 单次 LLM 调用 + "绝对不要编造"。没有地方放智能，也没有地方放账本。
2. **阶段二（补丁期）**：8→12 轮循环、工具逐个打补丁、双轨推导、防御复制、契约漂移。教训：稳定性没有长在结构上，长在了词表和重复校验上。
3. **阶段三（当前）**：断言/投影分层、统一工具注册表与预算、事务化写入、archive@2、ego 实体、双通道回答。**结构收敛基本完成，但输出契约仍只有"正面事实"一种形状，这是当前的主要残余。**

---

## 3. 为什么矛盾看起来不可调和（不变的核心）

- LLM 有理解力无确定性；本地代码有确定性无理解力；用户输入自由、含混、充满否定与指代。
- LLM 降低了理解成本，**没有降低验证成本**——这个品类的壁垒是"让验证成本最低"：依据、溯源、撤销、一键批准。
- "自动"与"可信"只能靠第三个角色"人"化解：AI 提议、本地执行、人签字。签字的正确形态是收据，不是收费站。

---

## 4. 边界原则（此后一切改动的判据）

- **P1 谁生产事实，谁承担审计**：AI 事实必须携带可回查依据，确认前保持待核验。审计责任不可放宽，可放宽的是确认粒度。
- **P2 确定性只做可证明的闭包**：本地只投影（亲属、路径、排序、去重），不从自由文本猜语义。
- **P3 理解权归模型，执行权归本地**：模型提议目标/意图/标签；本地校验 ID、锁排序、事务写库。
- **P4 任何正则/词表必须配正反例语料**：否则它就是在假装理解，应删除或改为 AI 提案。
- **P5 写入只走一条路径**：一切 AI 输出只能成为提案，经唯一事务入口提交，可整体撤销。
- **P6 用户不承担本地规则的错误**：确定性代码错了就删规则，而不是增加人工步骤让用户擦屁股。
- **P7 信任可调，账本不可调**：批准粒度可调（逐条/汇总/全自动），但事务、撤销、日志、校验、禁止外发、急症路由永不关闭。
- **P8 结构优先于补丁**：任何问题出现，先问"哪个结构缺少了第一类表达或通道"，再决定是否加规则、加工具。每加一个局部机制，必须同时说明它最终合并进哪个现有结构。反例：为"缺哪些信息"新增 `get_archive_gaps` 工具是补丁；正解是把答案输出类型化为 claim kinds（fact / gap / advice / language / uncertain）并各配一个本地渲染器，一次解决"缺失、否定、诊断"整类内容。
- **P9 用户优先于非底线核验**：核验分两级。
  - **底线核验**（不可让步）：生命健康急症、法律与政治合规、不自动外发、不泄漏密钥与联系方式。
  - **非底线核验**（格式、通道分离、软性审计）：**不得以隐藏答案、空回答、多轮重试破坏用户体验**。失败时默认降级为"可见的未核验/待确认提示"，绝不吞掉答案，绝不把内部错误抛给用户。

### 5.2 未解决（当前靶子）

**U1 输出契约只有"正面事实"一种形状（本次暴露）**
- 现象：模型把"某人的某字段缺失"写成 `archiveClaims[{sourceRef, field}]`（无 quote）；渲染层不认 → `citationCount: 0` 静默放行；用户只看到抽象的 ①–⑤。
- 结构性解法（按 P8，不是加 gap 工具）：**把模型输出声明类型化为 claim kinds**——`fact`（sourceRef+quote，本地生成规范句）、`gap`（sourceRef+field，本地由字段审计器渲染"张三：缺联系方式"）、`advice`（自由建议）、`language`（语言问答）、`uncertain`（资料不足）。每类一个本地渲染器；渲染失败 = **可见的"未核验"提示**，永不静默丢弃（按 P9）。
- 这是当前唯一的 P0 结构项。

**U2 数据结构残留（赛后）**
- "我↔某人"的关系仍是两套真相：`profile.relation` 字符串 vs 关系断言表；
- `profile.extra` 是无 schema 黑箱；
- caseEvents/tasks/projects 等企业版库与面板仍在。

**U3 日志默认档（X3 残留）**
- `savePrivatePayload` 默认 false，"复制 JSON"仍是结构骨架；三档（关闭/脱敏正文默认/仅结构）未做。

**U4 多轮追问边界（X5 残留）**
- 历史轮次的图片不重发；超过 8 轮静默遗忘无提示。

**U5 8/31 外部门**
- 真实模型全矩阵（DeepSeek 回归"我的初恋""缺哪些信息"）、Cloudflare 实部署、信息表与邮件提交。

## 6. 具体决策的裁决

- **A 圈层**：collections/memberships 已是唯一真相；`AUTO_RULES` 式语义猜测不得回归；AI 圈层修改走提案流。
- **B 目标意图**：模型提议，本地校验 ID 并锁路径/排序；不再扩充本地意图词表。
- **C 急症**：只保留"持续胸痛伴冷汗、无呼吸/呼吸停止、大出血"三个硬短语；其余交模型 + 顶部安全提示。
- **D 数据卫生**：赛后按缺陷清单处理，不抢占 8/31。
- **E 授权**：三级（谨慎/标准/full access），默认标准；full access 在事务与撤销测试全绿后开放。P9 优先级：任何授权档都不改变底线核验，但非底线核验只能降级为提示、不得阻断体验。
- **F 输出契约类型化（新增）**：实施 U1 的 claim kinds；**不再为具体问题类型新增专用工具**。所有"档案诊断类"问题（缺什么/哪些可疑/哪些没挂人）都落到 `gap`/`uncertain` 两种声明与对应本地渲染器上。

---

## 8. 一句话总结

> 让概率性的智能负责理解，让确定性的账本负责事实，让人负责签字；**结构优先于补丁，用户优先于非底线核验。** 每次这三句话被违反，bug 都会以"抽象答案、静默丢失、内部错误"的形式回到用户面前。
