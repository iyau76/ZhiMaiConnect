# 关系网显示链路

关系网有两条显示链路，用人物关系页工具栏里的「原版／新版（测试）」开关切换，默认原版。
两条链路共用同一份事实（`collections` / `collection_memberships`）、同一个相机与同一套屏幕标签。

## 为什么有两个版本

原版把「一个人属于哪几个圈层」拼成一个稳定的**成员组合**，每个组合画一个簇。
好处是从不丢成员关系，代价是圈层之间不可能相交，组合数随圈层数增长（三体演示库 9 个圈层被拆成 15 个簇），
环套环的几何又把画布撑大，界面上表现为「中心大片空白 + 名字只有两三像素」。

新版把圈层当成集合：一个人只有一个节点，可以同时落在多个圈层的外形里，交集处自然重叠。
新几何是确定性两层布局（圈层锚点 + 人物松弛 + 棚架打包），不再围成一个大圆。

新版仍在验证，所以默认不启用；开关状态存在 `zhimai:graph-layout-version`。
录入页预览跟着同一个开关走：预览承诺和入库后看到的是同一张图。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `src/lib/circle-membership-projection.ts` | 事实视图：圈层、每个人的所属圈层、真实两两交集。跳过 `computed` 成员与 `context` 集合 |
| `src/lib/relation-graph-layout.ts` | 新版纯几何：两层布局、连通分量打包、`applyGraphPins` |
| `src/lib/set-contours.ts` | 新版包络：成员凸包 + 扩张半径，并校验「成员在内、非成员在外」 |
| `src/lib/graph-camera.ts` | 相机：世界 ↔ 屏幕换算、适应内容、缩放锚点 |
| `src/lib/graph-labels.ts` | 屏幕标签：真实字体测量、8 个候选位、避让、密度抽样、位置延续 |
| `src/lib/relation-graph-legacy.ts` | 原版：成员组合投影、环套环几何、跟着成员流动的不规则外形 |
| `src/lib/graph-layout-version.ts` | 版本开关的读写 |

`relations-panel.tsx` 只负责把数据接到几何与渲染上；`draft-graph.tsx`（录入页预览）复用同一批纯函数。

## 不变量

- **一个人一个节点。** 名称不是主键；圈层数量由真实集合决定，不由成员组合决定。
- **成员关系不静默丢弃。** 新版一个人可以属于任意多个圈层；原版用组合簇保证不丢。
- **包络是校验过的。** 画出来的区域严格等于「成员凸包 + 扩张半径」：成员节点一定在内，非成员节点一定在外
  （`contourVerdict`）。凸包会误包站在成员中间的人时，这一层拆成几段同色轮廓，最坏情况退到逐个成员的小外形；
  分片比把别人圈进「亲属圈」更诚实。
- **确定性。** 没有 `Math.random`、没有时间戳；输入按稳定 ID 排序，迭代轮数固定，结果量化到 1/1024。
  拖动只走 `applyGraphPins`，不会重跑迭代，也不会改变自动边界。
- **横竖屏是两套布局类别。** 首次测量决定，之后旋转只调整镜头；避免拉一下窗口就把所有人重排。
- **文字在屏幕空间。** 字号是 CSS px，缩放改变的是名字之间的距离，不是名字本身的大小。
  人多且屏幕间距小于 68px 时，按圈层隔一个显示一个名字；放大以后自己回来。被抽掉的名字靠悬停气泡和搜索仍然可达。

## 验证

- 单测：`src/lib/{circle-membership-projection,relation-graph-layout,set-contours,graph-camera,graph-labels,relation-graph-legacy,graph-layout-version}.test.ts`
- 端到端：`e2e/graph-layout-version.spec.ts`（默认原版、切换新版、选择被记住）、
  `e2e/core-flows.spec.ts`（关系网交互）、`e2e/resilience-and-scale.spec.ts`（51 人 91 关系）、
  `e2e/pr3-compatibility.spec.ts` 与 `e2e/family-tree.spec.ts`（家族树沿用专用几何）

## 已知缺口

- 新版包络不做凹形绕行：遇到非成员时用分片，而不是把轮廓绕成凹形（Bubble Sets 式）。
- 没有矩阵／交集表视图，三重以上交集只能靠选择多个圈层查成员表。
- 手动拖动的位置只存在本次会话里，没有版本化与增量布局。
- 200 人 / 20 圈层的纯几何约 100ms（本机 Node 22），只保证布局变化时重算，不在每帧跑。
