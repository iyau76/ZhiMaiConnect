# 应用更新

| 渠道 | 更新方式 | 现状 |
| --- | --- | --- |
| 网页 / PWA | 浏览器 + Service Worker 自动更新；设置里可手动触发 | 已实现：`src/lib/pwa-client.ts` + `pwa-controls.tsx` |
| Windows / Android 安装包 | 设置 →「关于与更新」→「检查新版本」，以 GitHub Releases 为更新源 | 已实现：`src/lib/update-check.ts` + `src/components/about-controls.tsx` |

## 更新源

仓库固定为 `iyau76/ZhiMaiConnect`，读 `GET /repos/iyau76/ZhiMaiConnect/releases`：

- 跳过 `draft`，取已发布版本里版本号最高的一个（`compareVersions` 自己比，不依赖 GitHub 的排序）。
- 预发布版本比同号正式版小：`v0.3.1-preview.1 < v0.3.1`，所以预览版不会把正式版用户推去下载。
- 安装包按运行平台挑：Windows 取 `.exe`，Android 取 `.apk`，网页版不取文件（提示重开即更新）。
- 失败一律降级成「没能查到」，并把原因（`GitHub 返回 403` / `请求超时` / `连不上 GitHub（可能需要代理）`）显示出来，同时保留「打开发布页」入口。
  检查更新不是底线能力，失败不能拦住用户用应用，也不能假装已经是最新。
- 原生壳走自带网络栈（`platformFetch`），网页版直接 `fetch`；请求带 8 秒超时。

## 版本号单一来源

`scripts/sync-version.mjs` 以**根 `package.json`** 为准，同步到：

- `src/lib/app-version.ts`（界面显示与「检查更新」的当前版本）
- `desktop/package.json`（electron-builder 的 `${version}`，决定 Windows 安装包名）
- `android/app/build.gradle`（`versionName`；版本变化时 `versionCode` 自动加一）

```bash
node scripts/sync-version.mjs          # 按根 package.json 对齐其它文件
node scripts/sync-version.mjs --check  # 只校验，不一致退出码 1
```

发版顺序：改根 `package.json` 的版本 → `npm run version:sync` → 提交 → `npm run package:windows` / `package:android`
（两个打包脚本开头都会先跑 `--check`，版本没对齐就直接失败，避免打出名字和实际版本不一致的包）
→ `release/github-release.mjs` 上传 GitHub Releases（draft → 校验 sha256 → publish）。
`checkForAppUpdate` 只看已发布版本，所以草稿阶段不会提示用户更新。

## 验证

- 单测：`src/lib/update-check.test.ts`（版本比较、按平台挑包、草稿跳过、403/断网/空列表降级）
- 端到端：`e2e/update-check.spec.ts`（查有更新 / 已最新 / GitHub 报错三条路径，GitHub API 全程 mock）
- 真实数据源核对：`v0.3.1-preview.1` 是当前最新发布，资产含 `win-x64-setup.exe` 与 `-test.apk`；当前版本 0.3.1 判定为已最新。
