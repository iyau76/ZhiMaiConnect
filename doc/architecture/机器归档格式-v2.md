# 知脉 Connect 机器归档格式 v2

## 为什么不能继续使用 `archive@1`

旧格式导出的是 `listRelations()` 的兼容视图。这个数组同时含人工/材料事实和本地规则生成的派生边，恢复方无法可靠区分“用户确认过的事实”与“某一版算法的缓存”。此外，它遗漏了当前数据模型的证据链接、展示与引荐策略、集合/成员关系、任务和项目等数据。因此旧文件只能算部分备份，不能作为新数据模型的长期契约。

`zhimai-connect/archive@2` 采用以下边界：

- `records.relationAssertions` 是关系事实；同一事实可以保留多条独立 assertion 和各自证据，不按人物姓名或显示标签去重。
- `projectionDiagnostics.derivedRelations` 只是导出时的诊断快照。导入时必须丢弃，并由当前版本的 `kinship-projector` 从已确认 assertion 重建。
- 展示偏好、引荐策略和事实分开保存，修改“常隐”“不用于引荐”不会篡改事实的更新时间或来源。
- `collections` 与 `collectionMemberships` 是持久集合；不再把 `person.profile.circle` 当唯一圈层真相。旧字段仍保留，以便兼容和人工核对。
- 新人物与圈层可在同一录入草稿中批准。草稿成员引用临时人物 ID，入库时沿用人物身份决定转换为正式 ID，人物、集合与成员写入同一事务；撤销恢复原集合及成员。临时引用不进入 archive@2，已有备份无需迁移。
- 模糊事件同时保存 `dateText` 原话和 `date` / `dateEnd` 归一化范围：原话负责忠实呈现，范围负责排序与投影。
- 事件的 `timeText` 独立保存具体时间原话（例如“下午3点”），不受日期精度影响。`date`、`dateEnd`、`precision` 负责日期范围，`dateText` 保留模糊日期说法；不从原话猜测时区或强行生成时间戳。
- 提醒完成后补记的互动是一条独立 `lifeEvent`，提醒只用 `completionEventId` 指向它。删除事件会在同一事务中解除该引用，不复制事件正文。
- `meetingBriefs` 保存见面简报的版本快照及逐条来源引用。事实变化只会把旧版标为“有更新”，生成新版时保留旧版供回看。

## 顶层结构

```json
{
  "schema": "zhimai-connect/archive@2",
  "exportedAt": "2026-08-28T10:00:00.000Z",
  "generator": {
    "app": "zhimai-connect",
    "appVersion": "0.1.0",
    "dataModelVersion": 13
  },
  "privacy": {
    "mode": "safe-default",
    "containsPrivateText": true,
    "warning": "……",
    "omissions": []
  },
  "records": {
    "persons": [],
    "relationAssertions": [],
    "relationEvidenceLinks": [],
    "relationViewPreferences": [],
    "referralPolicies": [],
    "collections": [],
    "collectionMemberships": [],
    "evidence": [],
    "caseEvents": [],
    "tasks": [],
    "projects": [],
    "lifeEvents": [],
    "reminders": [],
    "meetingBriefs": []
  },
  "projectionDiagnostics": {
    "importPolicy": "discard-and-rebuild",
    "projectorVersion": 2,
    "derivedRelations": []
  }
}
```

JSON“完整备份”不再受当前页面的导出范围影响：无论从人物页还是事务页点击完整备份，均读取上述全部持久记录。Markdown、Word、PDF 仍是方便阅读的展示格式，不是恢复格式。

## 可恢复范围

以下数据属于 v2 的持久记录，经过严格校验后可原样进入恢复计划：

- 人物档案，包括 `entityRole`、`identityScopeId`、字段来源、身份别名和扩展字段；
- 关系 assertions、assertion—evidence 多对多链接；
- 关系展示偏好与引荐策略；
- 用户/AI 批准的集合和成员关系；
- 文本证据、案件时间线、任务、项目、个人日历事件和提醒；
- 已保存的见面简报。每一版保存 `seriesId`、上一版 ID、源记录 ID 与生成时修订值，简报中的事实句可以回到人物、关系、事件、提醒或任务。

“可恢复”不等于“无提示覆盖”。恢复界面先显示新增、覆盖、冲突和删除预览；全量替换由 `replaceArchiveSnapshot` 在一个 IndexedDB 事务内完成，并在提交后重建关系投影。完整备份显式提供 `meetingBriefs` 时会替换该集合；事实变更的撤销检查点没有携带该字段时会保留简报，避免撤销一条事实时误删历史产物。

见面简报是可追溯快照，不是人物事实的第二份真相。人物、关系、事件、提醒或任务修改后，系统比较源记录的当前修订值与简报中的 `sourceRefs`，只提示需要更新；用户生成新版后，旧版仍然存在。删除人物属于隐私删除边界，会同时删除该人物的简报；删除或修改其它来源记录不会改写旧简报。

## 默认排除的数据

机器备份本身包含联系人、关系依据、联系方式和事务正文，应当按敏感个人数据保管。安全默认值会排除：

- 人物照片、事件照片和证据缩略图；
- 人脸 descriptor、人脸缩略图、摄像头 sightings、声纹向量；
- 模型 API 密钥、会话凭据和环境变量（导出代码从不读取这些位置）；
- Agent 私密日志正文、会话草稿和浏览器配置。

排除项及数量会写进 `privacy.omissions`，避免用户误以为照片或生物特征已经备份。若未来允许单独导出媒体/生物特征，应设计独立、显式选择且加密的包，不能静默扩大 `archive@2`。

## 导入与校验

实现位于 `src/lib/archive-data.ts`：

- `normalizeArchive(input)`：解析 JSON，严格检查对象字段和枚举，再检查 ID 唯一性及人物、关系、证据、集合、项目等跨表引用。
- `archiveRestorePlan(input)`：只返回 `records`，并明确要求重建派生关系；`projectionDiagnostics.derivedRelations` 永远不会进入事实表。
- 未知字段会被拒绝，而不是由 Zod 静默剥离；未知 schema 也会给出明确错误。

导入流程应按以下顺序执行：

1. 只在用户选择“恢复机器备份”时调用 `normalizeArchive`，不要把整个备份作为自然语言交给 AI。
2. 显示隐私告警、旧版迁移告警、记录数和冲突预览。
3. 用户选择“合并”或“完整替换”，并批准具体计划。
4. 在统一事务中写持久记录。
5. 丢弃归档中的派生快照，运行当前 projector，并报告新旧投影差异。

现有普通文件录入入口已经在读取 `.json` 时识别 `zhimai-connect/*` schema：识别到机器备份会停止拼接文本并提示改走恢复流程，避免完整私人档案被截断后发送给模型。该保护不等于恢复 UI；恢复页面仍需实现上述预览与统一事务。

## 旧格式兼容

事件时间扩展采用可选字段，现有 IndexedDB 记录无需批量改写，缺少 `timeText` 就表示未记录钟点。新旧备份均可由新版读取；新备份携带的该字段在恢复、撤销和编辑时保留。旧程序会拒绝含此字段的新备份，因此回滚程序时应先保存新版完整备份，继续保留数据库原记录，恢复时使用新版解析器。已经被旧版丢弃的钟点不能从日期恢复，需要原始材料或用户补充。

`normalizeArchive` 支持应用曾经生成的：

- `zhimai-connect/archive@1`；
- `zhimai-connect/projects@1`。

迁移规则不是“把旧数组原封不动写回”：

- 只有明确关系或旧版无法判定但未标为推导的记录才迁移为 assertion；
- `recordType=derived`、`evidenceMode=inferred`、含 `derivedFromRelationIds` 或依据以“推断依据”开头的记录，只进入诊断快照；
- 旧关系的 `visibility` 和 `recommendationPolicy` 分别迁移为独立策略；
- `profile.circle` 转成确定性 collection 与 membership，同时保留原字段；
- `zhimai:self`（或旧档案中的“我”）迁移为 `entityRole=ego`；
- @1 没有导出 evidence 表，因此孤立 `sourceId` 不会被伪造成证据链接；`basis` 与来源说明仍保留，并给出迁移告警；
- 旧文件中的照片、descriptor 和缩略图会按 v2 安全默认值排除。

这些规则保证旧文件仍可读取，同时不把旧推导算法产生的“幽灵边”升级为新的事实。
