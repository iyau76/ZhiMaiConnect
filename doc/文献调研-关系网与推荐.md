# 文献调研：关系网络展示与"找人办事"推荐（定向侦察版）

> 检索日期：2026-08-27 ｜ 用途：支撑"关系网太乱 / 解剖式分层 / 找贾母办事该通过谁"三项反馈的 P0 决策
> 检索源：CrossRef（T1，DOI 级核验）+ OpenAlex（skill 无 MCP 时的回退检索，经代理 127.0.0.1:7897）
> 结论：三项反馈各对应一套成熟学术方案，全部可直接落地到 50–200 节点小图，无需任何深度学习。

## 0. 一句话结论（可直接写进产品信息表）

> 借鉴 **Referral Web 的引荐链模型**、**主题敏感 PageRank 的目标导向排序**，以及 **tie-strength 边显著性 + Motif Simplification 派生边折叠**，实现"少而准"的个人关系网络：默认只显示显著关系，路径搜索按"我→中间人→目标"逐跳打分。

## 1. 三个反馈 → 学术答案（总表）

## 2. 核心文献卡片（12 篇，全部 DOI 经 CrossRef 核验）

引用数为 OpenAlex 2026-08-27 快照，仅用于判断"是否为领域公认经典"，不用于相互攀比。

### A. 边显著性（决定什么边常显、什么边折叠）

**A1. Granovetter, *The Strength of Weak Ties*, AJS 1973**（c≈38,831，DOI 10.1086/225469）
核心：关系强弱是社会网络行为的核心变量；两个个体的朋友圈重叠度随关系强度而变。
→ 知脉：边不能"有就画"，必须带强度。我们的亲密度 1–5、共同事件、互动新鲜度都是现成的强度证据。

**A2. Marsden & Campbell, *Measuring Tie Strength*, Social Forces 1984**（c≈1,269，DOI 10.1093/sf/63.2.482）
核心（原文摘要可核）：关系强度大致有"相处时间"与"关系深度"两个侧面；**"亲密/强度"是最好的单一指标**；单独用频率或持续时间有测量缺陷。
→ 知脉：`closeness` 应占最高权重；只拿"最近联系时间"当强度的做法要修正（我们正有此倾向，见第 3.1 节公式）。

**A3. Gilbert & Karahalios, *Predicting Tie Strength with Social Media*, CHI 2009**（c≈1,382，DOI 10.1145/1518701.1518736）
核心：把社交平台数据映射为 tie strength；预测模型基于 7 个维度——强度(intensity)、亲密度、持续时间、互惠服务、结构嵌入、社会距离、情感支持。
→ 知脉：7 维可逐一映射到现有字段：亲密度→`closeness`，强度→互动频次，持续时间→`createdAt`，互惠→`mutual`+共同"帮忙"事件，结构嵌入→共同联系人数，社会距离→关系类型先验（家人>亲戚>同学/同事>认识），情感支持→`note`/事件语义（当前缺，可留 0 默认，不阻塞）。

**A4. Dunne & Shneiderman, *Motif Simplification*, CHI 2013**（c≈201，DOI 10.1145/2470654.2466444）
核心（原文摘要可核）：把常见节点-链接模式替换为紧凑且有语义的字形（glyph），收益是省空间、易读、**能揭示被隐藏的关系**、尽量保留底层信息。处理的三种高频 motif：fan（多节点共连一个节点）、connector（连接一组锚点）、clique（完全连通团）。
→ 知脉：这正是"同一人儿女"的官方解法——"同一父母的子女"就是 fan/团 motif，默认折叠成"子女组"一个字形，点开才散开；折叠不删数据，底层关系仍在。

### B. 分层展示（"解剖"的学术原型）

**B1. Furnas, *Generalized Fisheye Views*, CHI 1986**（c≈1,640，DOI 10.1145/22339.22342）
核心（原文摘要可核）：人看世界是"近处详细、远处只留地标"；fisheye 用 **Degree-of-Interest(DOI)** 函数统一控制信息量。
→ 知脉：我们的"层"就是 DOI 的离散化：tie 分数≥阈值进核心层，否则进上下文/隐藏层。

**B2. van Ham & Perer, *"Search, Show Context, Expand on Demand"*, TVCG 2009**（c≈232，DOI 10.1109/TVCG.2009.108）
核心（原文摘要可核）：对半具体的信息需求，**不要先渲染全图**，而应：搜索定位目标节点 → 只显示该节点周围有意义的上下文子图 → 用户按需展开。DOI 函数从树推广到图。
→ 知脉：这就是"解剖式分层"的教科书版交互流程。对应实现：① 搜索/点选某人；② 显示他+强关系一阶邻居；③ "展开"按钮逐层加人。50 节点时按需展开比一次性全图渲染更顺、更符合评委期待。

**B3. Holten, *Hierarchical Edge Bundles*, TVCG 2006**（c≈987，DOI 10.1109/TVCG.2006.147）；Holten & van Wijk, *Force-Directed Edge Bundling*, CGF 2009（c≈534，DOI 10.1111/j.1467-8659.2009.01450.x）
核心（摘要可核）：边捆绑显著减少视觉杂乱、显露高层边模式；层次化版本还能把"子节点间多条显式边"呈现为"父节点间一条隐式边"。
→ 知脉：P2 备选。我们现在按 tag 环形分簇，若 50–200 人全显时边乱，可把簇间边按同 tag 捆绑；**注意**：隐式边聚合的语义和"派生边折叠"一致，先做 A4 的折叠，捆绑留到数据变大再说。

### C. 找人办事 / 路径搜索（修"通过谁找贾母"的排序）

**C1. Kautz, Selman & Shah, *Referral Web*, CACM 1997**（c≈852，DOI 10.1145/245108.245123）
核心：从公开网页的共现挖掘社交网络，构造 **referral chain（引荐链）**，回答"通过谁联系某人/谁认识谁"这类查询。
→ 知脉：这就是我们的"通过谁找贾母办事"的原题。他们给的是**链式答案**（你→甲→乙→目标），不是"一个得分最高的人"。所以产品要新增路径模式：输出链 + 每跳依据，而不是把贾琏塞进普通候选列表。

**C2. Dodds, Muhamad & Watts, *An Experimental Study of Search in Global Social Networks*, Science 2003**（c≈888，DOI 10.1126/science.1081058）
核心（摘要可核）：6 万条真实邮件转发链实验表明——成功的社交搜索主要走**中弱关系**，不依赖高度连接的"枢纽"，并且**不成比例地依赖职业关系**。
→ 知脉：直接解释上次的错排：全局 PageRank 会奖励"同学集群枢纽"，而实验证据是"弱关系+职业关系"才是有效传递通道。因此排序应从"目标人出发找路"，而不是"全网声望最高的中间人"。

**C3. Haveliwala, *Topic-Sensitive PageRank*, WWW 2002**（c≈1,548，DOI 10.1145/511446.511513）
核心（摘要可核）：单一全局 PageRank 与查询无关；改为按主题偏置的一组 PageRank 向量，重要性随主题变化。
→ 知脉：如果要用 PageRank，必须**主题/目标偏置**（Personalized PageRank 以"我"和"目标人"为种子），不能用全局 PR。且 PPR 每个查询重算，50 节点下 20–30 轮幂迭代毫秒级，性能无压力。

**C4. Serdyukov, Rode & Hiemstra, *Modeling Multi-Step Relevance Propagation for Expert Finding*, CIKM 2008**（c≈116，DOI 10.1145/1458082.1458232）
核心（标题+摘要可核）：专家定位不能只做"文档→人"一步传播；构造 expertise graph，让相关性在**人-文档-关系多步传播**。
→ 知脉：把"任务词→人"一步匹配升级为"任务词→事件/档案→人→关系→更多人"的多步传播。这正是 `rankCandidates` 缺 `relations` 参数的学术版本（当前实现见 `src/lib/recommendation.ts:89`，只有 task/persons/events 三个输入）。

**C5. Lao & Cohen, *Relational Retrieval Using Path-Constrained Random Walks*, Machine Learning 2010**（c≈637，DOI 10.1007/s10994-010-5205-8）
核心：按**路径类型**（path type）分别学习权重，再聚合打分——比"任何路径一视同仁的随机游走"更准、更可解释。
→ 知脉："通过配偶的兄弟"和"通过大学同学"是不同路径类型，应分开打分再聚合，且**路径类型本身可作为解释文案**（"他与你共同参加过 X，且是目标人的同事"）。

**C6. Freeman, *A Set of Measures of Centrality Based on Betweenness*, Sociometry 1977**（c≈10,388，DOI 10.2307/3033543）
核心（摘要可核）：betweenness 衡量"一个点落在多少最短路径上"，即**对沟通的控制潜力**。
→ 知脉：找"桥梁人"用 betweenness 局部值（中间人是否处于"我→目标"路径上），不用全局 PR。在 50 节点图上直接数最短路径即可，不必引入复杂近似算法。

**C7. Lin et al., *SmallBlue*, ICDE 2009**（c≈92，DOI 10.1109/ICDE.2009.140）
核心（摘要可核）：IBM 企业内系统，回答 "who knows what / who knows whom / who knows what about whom"，帮助用户通过"朋友的朋友"找到专家。
→ 知脉：我们的产品定位可引用为同类先例——个人版 SmallBlue。产品文案可用这三个 who 问题组织"找人办事"场景。

### D. 可读性兜底（P1，文献支撑阈值选择）

**D1. Purchase, *Effective Information Visualisation*, Interacting with Computers 2000**（c≈125，DOI 10.1016/S0953-5438(00)00032-1）与 **Yoghourdjian et al., *Exploring the Limits of Complexity*, Visual Informatics 2018**（c≈95，DOI 10.1016/j.visinf.2018.12.006）：图可视化的经验评估与复杂度上限研究。
→ 知脉：折叠/隐藏阈值不是拍脑袋——引用"人类对节点-链接图的可读规模存在经验上限"作为自动折叠的学理依据（具体数字待实现时按这两篇的经验区间校准）。

**D2. Nobre et al., *The State of the Art in Visualizing Multivariate Networks*, CGF 2019**（c≈144，DOI 10.1111/cgf.13728）：多变量网络（拓扑+节点/边属性）可视化综述。
→ 知脉：边属性编码规范：**线宽=显著性，颜色=关系类型，虚线=待核验/AI 推断**。和现有 `_audit`/pending 徽标一致。

## 3. 可直接实现的方案（伪代码级）

### 3.1 边显著性 `tie(u,v)`（P0，纯本地计算）

输入全部来自现有数据（`RelationRecord`、`PersonRecord.profile.closeness`、`LifeEventRecord`）：

```
tie = 0.30 * closeness01          // (closeness-1)/4，closeness∈1..5
    + 0.30 * recency              // 最近互动: ≤30d=1; ≤180d=0.7; ≤365d=0.45; 更早=0.2; 无记录=0.15
    + 0.15 * frequency            // 近一年互动次数 min(n/12, 1)
    + 0.10 * duration             // 关系年限 min(years/5, 1)，旧数据用 updatedAt 回退 createdAt
    + 0.15 * typePrior            // 父母/子女/配偶/兄弟姐妹=1；亲戚=0.8；同学/同事/朋友=0.6；认识=0.35；其他=0.5
tie *= (confirmationStatus === "pending" ? 0.6 : 1)
```

阈值（初始值，产品内做成可调常量）：

- `tie ≥ 0.65` 或 关系类型为直系亲属 → **核心层**（常显）
- `0.40 ≤ tie < 0.65` → **上下文层**（定位到某人时显示其一阶邻居）
- `tie < 0.40` 或 `derived = true` → **按需层**（默认隐藏，侧边栏可勾选显示）

单边覆盖：新增 `RelationRecord.visibility?: "always" | "hidden" | "auto"`。用户手动设"常显/常隐"后**完全绕过公式**（人是最终裁判，符合 human-in-the-loop 原则）。新增 `derived?: boolean` 标记 AI/规则推导出的派生边（如兄弟关系），默认进按需层。

### 3.2 分层展示（P0，复用 van Ham & Perer 交互）

1. **Search**：搜索/点选一个人 → 不清空其它，但高亮该人；
2. **Show Context**：只显示该人 + `tie≥0.40` 的一阶邻居 + 共同事件计数；
3. **Expand on Demand**：侧边栏三层开关（核心/上下文/按需）+ 关系类型过滤（现有 `relationFilter` 保留）+ "展开子女生组"字形。

fan/团 motif 折叠规则：≥3 人共享同一"父/母"边 → 折叠为"子女组"字形；<3 人时维持两两边（图小，折叠反而费解）。

### 3.3 路径模式排序（P0，替换"用 PageRank 找中间人"）

新增 `rankConnectors(source, target, task, persons, relations, events)`（现 `rankCandidates` 增加 `relations` 参数或另起函数，不改其现有单目标语义）：

```
对每个中间人 m ∈ (source 的 1–2 跳邻居 ∩ target 的 1–2 跳邻居):
  pathScore(m) = Σ 路径类型 τ 权重(τ)
                 * tie(source, m)          // 第一跳强度
                 * tie(m, target)          // 第二跳强度
                 * 主题相关度(target, task) // 目标人能否办事（Haveliwala 主题偏置）
                 * (τ 为"职业/帮忙"类路径 ? 1.2 : 1.0)   // Dodds: 职业关系加成
  + 0.05 * betweenness(m) 的局部版        // Freeman: 桥梁加成，仅小权重
输出：路径链 + 每跳依据（basis/note/共同事件） + 总信心
```

要点：

- **以目标人为锚**：找贾母就是"谁离贾母近、离我也近、且这条路径走得通"，同学 hub 若与贾母无路，自然排到贾琏后面；
- **逐跳相乘而非相加**：某跳是 pending 推断边时乘 0.6，与 3.1 一致，保证"AI 推断"自动降权、待核验可见；
- **PPR 备选**：开放型任务（不指定目标，如"找人帮忙改 PPT"）用 PPR：种子=任务词命中的候选集，按 `tie` 转移概率做 20–30 轮幂迭代，给每个"人"算传播得分，并记录其最大概率来源路径作解释。

## 4. 明确不读 / 不做的方向（省时间）

| 方向 | 不做的理由 |
|---|---|
| 社区发现（Louvain / Leiden） | 50–200 人的图直接肉眼看簇，社区检测无增益 |
| GNN / 图嵌入 / 知识图谱嵌入 | 规模不够，训练不成立；且解释性差，比赛答辩吃亏 |
| 影响力最大化、信息扩散模型 | 与"找人办事"目标不同 |
| 布局算法文献 | 现有环形分簇够用，边捆绑（B3）仅作 P2 备选 |
| 全局 PageRank / HITS | C2/C3 已证伪"全局声望"思路，只保留目标偏置版本 |
