## 修复与依据

| 问题 | 根因与本次处理 | 验证 |
| --- | --- | --- |
| B01 人物局部字段导致整项丢失 | 语义输出与存储结构之间缺少逐字段解码。有效字段继续生成草稿，不能直接归入固定属性的内容进入现有事实草稿，保留原字段名和值，供用户编辑。未增加同义词特判。 | 编译器测试覆盖未知字段、错误字段类型及其关联圈层、事件。 |
| B02 具体钟点丢失 | 原保存逻辑将 timeText 当作模糊日期的替代品，精确到日时清空。事件现有结构增加独立可选 timeText；录入、日历编辑、工具读取、导出与恢复共同保留。 | 真实 API 草稿入库后，在日历编辑页和完整备份中均可读到“下午3点”；旧备份仍可恢复。 |
| B03 新人物圈层消失 | 集合提案执行要求归档人物 ID，待批准的新人物尚无此 ID。圈层成员现在可以引用同一草稿中的稳定临时人物 ID，批准时统一解析并与人物原子提交；撤销时恢复旧成员和圈层。 | 新人物、已有成员、新旧混合、补充成员、未解析引用和撤销测试；真实界面保存两个新圈层。 |
| B04 今天看不到待批准录入 | 消费端把“不支持继续推理”误当成“不需要处理”。awaiting_approval 现在独立进入今天工作台。 | 单元测试与运行中切换今天页面的真实浏览器观察。 |
| B05 未来约定被称为上次 | 简报按所有事件倒序直接取第一条。现按查看日分开既往经历与未来/持续约定。 | 确定日期、跨日范围和具体时间测试。 |
| B06 已有关系仍提示缺失 | 简报只检查人物 profile.relation，遗漏已确认的自我关系断言。现读取正式关系及其方向，作为关系说明和缺口判断依据。 | 已确认自我关系与旧字段兼容测试。 |
| B07 圈层与标签筛选混淆 | 两套同名入口读取不同数据。档案页新增基于 collections/memberships 的圈层筛选；标签只展示已有标签，不再以预设标签冒充圈层。 | 浏览器手工建圈层后的筛选测试；真实新圈层筛出两位成员。 |
| B08 已保存任务不能完整编辑 | 任务卡仅开放状态和负责人。现由任务标题打开编辑窗口，可改标题、详情、截止日期、负责人、关联人物、优先级及状态。 | 页面编辑、刷新、读取保存结果的端到端测试。 |
| B09 关系依据被换成圈层句 | 本地逻辑尝试用同时包含两端姓名的句子替换模型依据，代词句被无关句覆盖。现保留原依据，未对齐时显示软提醒。 | 原材料含代词关系句和另一条双姓名圈层句的测试；真实 API 关系依据未被改写。 |
| B10 手动身份选择及当前运行被覆盖 | 初始化清理可能先用空快照覆盖暂存；运行结果认领、旧页面焦点和检查点恢复又重复写入当前草稿。现明确暂存加载边界，草稿标记来源运行，已消费焦点只恢复一次，同一运行优先保留人工编辑；批准后同步运行投影。 | 刷新后保留目标档案选择并实际更新原人物；补充整理和后台认领回归。 |
| B11 未识别事件字段导致整项失败 | 实际模型一次返回 location，严格整项解析丢弃事件。事件和提醒同样使用逐字段解码，未建模内容保留在详情中；字段说明由现行 schema 生成。 | 未知 location、物料清单等字段测试；后续真实调用完整生成事件。 |

## 真实 API 验收

使用独立的可见 Chrome 上下文、本地 8080 服务和已有 DeepSeek 配置；人物均为合成数据。操作通过截图坐标点击、键盘输入与滚动完成。没有向用户原有浏览器人物库写入测试数据。

测试材料描述许星、陆遥的身份与朋友关系，约定 2026 年 9 月 8 日下午 3 点在青禾书店讨论读书会，提前一天带海报，并建立“读书会伙伴”和“街坊”两个圈层。

中间调用暴露过模型遗漏陆遥人物创建项、事件 location 字段不兼容的问题，不能将整个过程记作一次通过。修复后以包含补充材料的完整输入重新整理，结果为 7/7 项：两个人物、一条关系、一个事件、一条提醒、两个圈层。人工批准并保存后：

- “读书会伙伴”包含许星、陆遥，“街坊”包含许星，成员引用均指向实际归档人物。
- 日历中的“读书会讨论”保留日期和“下午3点”，编辑入口能够继续读取。
- 代词关系依据保留原句，并可由用户单独确认。
- 导出的 archive@2 完整备份保留具体时间和圈层成员。

本地证据保留在已忽略目录 `test-results/computer-use-20260905/`：080 为待批准入口；091 为 location 解析失败；094 为完整圈层草稿；098 为时间和地点草稿；099 为入库；102 为已保存时间；106 为圈层筛选。完整备份为 `知脉-完整备份-20260905-1310.json`。

## 剩余边界

模型仍可能漏掉材料中的某个人物或关系。此次改动解决的是本地丢弃有效内容、错写依据和新人物引用无法提交的问题，没有把模型抽取完整性当作已保证能力。无法唯一确定的人物仍需要人工选择；未建模字段保留为待整理信息，系统不擅自猜测它对应哪个属性。

新增 timeText 为向后兼容可选字段。旧版本已经丢失的钟点不会自动恢复，需从原始材料补录。此次真实调用针对一个复合场景；自动浏览器测试使用合成响应，以验证应用流程，不能代替对所有模型的能力评价。
